# Story 1.1: Initialize Project from Starter Template

Status: review

## Story

As a developer, I want a fully initialized TypeScript GitHub Action project with
build, test, lint, and bundle tooling, So that I have a working development
environment with CI/CD from day one.

## Acceptance Criteria

1. **Given** the `actions/typescript-action` template has been used to create
   the repo **When** I run `npm install && npm run all` **Then** the project
   compiles, lints, tests, and bundles to `dist/index.js` without errors
2. The following CI workflows exist and pass: `ci.yml`, `check-dist.yml`,
   `linter.yml`, `codeql-analysis.yml`
3. Node.js 20 is pinned in `.node-version` and `action.yml`
4. ESM is configured (`"type": "module"` in `package.json`, `.js` extensions in
   imports)
5. `@github/local-action` is available for local testing with a `.env.example`
   file
6. `action.yml` declares all inputs (`prompt`, `provider`, `model`, `paths`,
   `max_files`, `max_changes`, `label`, `branch_prefix`, `dry_run`, `base_url`)
   and outputs (`pr_url`, `pr_number`, `files_changed`, `lines_changed`,
   `skipped`)

## Dev Notes

### Architecture Requirements

- **Starter Template:** `actions/typescript-action` — canonical GitHub Action
  template maintained by GitHub
- **Bundler:** Rollup (replaces `ncc` from PRD — Rollup is the current best
  practice for Actions, provides tree-shaking and ESM support)
- **Runtime:** Node.js 20 pinned (overriding template default of >=24 to match
  GitHub Actions runner standard)
- **Module System:** ESM — `"type": "module"`, `.js` extensions in ALL imports,
  named exports only
- **Testing:** Jest with ESM support (`--experimental-vm-modules`), `__tests__/`
  directory structure
- **Code Quality:** ESLint + Prettier, strict TypeScript, no `any` types, no
  default exports, no `.then()` chains

### Target Project Structure (from Architecture)

```
Prompt2PR/
├── .github/workflows/ (ci.yml, check-dist.yml, linter.yml, codeql-analysis.yml)
├── .vscode/launch.json
├── dist/index.js (Rollup output, committed)
├── src/
│   ├── main.ts (action entrypoint: run())
│   └── index.ts (imports and calls run())
├── __tests__/main.test.ts
├── examples/ (empty for now)

├── action.yml

├── LICENSE

```

### Module/File Internal Structure Pattern

```typescript
// 1. Imports (external first, then internal, separated by blank line)
import * as core from '@actions/core'

import { ActionConfig } from './config.js'

// 2. Types/Interfaces (exported)
// 3. Constants
// 4. Main exported functions/classes
// 5. Internal helper functions (not exported)
```

### Naming Conventions

| Element              | Convention         | Example             |
| -------------------- | ------------------ | ------------------- |
| Files                | `kebab-case.ts`    | `git-manager.ts`    |
| Interfaces           | `PascalCase`       | `LLMProvider`       |
| Functions            | `camelCase`        | `createProvider()`  |
| Constants            | `UPPER_SNAKE_CASE` | `DEFAULT_MAX_FILES` |
| Action inputs (YAML) | `snake_case`       | `max_files`         |

### Key Constraints

- `dist/` must be committed to repo (required by GitHub Actions)
- No Docker — runs as a JavaScript Action (fastest cold start)
- No dependencies for LLM providers — direct `fetch` calls
- Template may use Node >=24 by default — MUST override to Node 20
